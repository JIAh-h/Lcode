# Client half: the renderer-side API

A plugin can extend the **interface**, not just the agent. This file covers that half.

The host half (`entry`, utility process) can register tools, prompt sections, and event listeners —
it **cannot** touch the UI at all. Anything visual needs a client half.

## Manifest

```json
{
  "contributes": {
    "client": {
      "entry": "./src/client.js",
      "slots": ["theme"]
    }
  }
}
```

| Field | Rules |
|---|---|
| `entry` | Package-relative `./…js`. Plain ESM JavaScript — **no TypeScript** (the renderer imports it directly). |
| `slots` | Which mount points to fill. At least one. Values below. |

Declaring `contributes.client` is independent of the host `entry`: you can ship only a client half
(the host `activate` can be an empty function), only a host half, or both.

## Slots

| Slot | Where it renders |
|---|---|
| `theme` | Nothing visible — applies CSS variables / background image globally |
| `sidebar.bottom` | Bottom of the left sidebar, above the account row |
| `conversation.top` | Above the conversation stream |
| `settings.section` | A panel in Settings |

A slot value outside this list is rejected at install time (`未知的界面插槽`).

## Entry shape

```js
export function render({ slot, api }) {
  // …return null (side effects only) or a node from api.h()
}
```

`render` is called on every React render of that slot. **Keep it pure**: it must not accumulate
state across calls. Module scope is fine for constants; for anything else, call `api.refresh()`.

Returning `null` means "nothing visible" — that is the normal return for `theme`.

## The `api` object

| Method | Purpose |
|---|---|
| `setCssVars({ '--x': 'value' })` | Override design tokens. Only `--custom-properties`, and the value cannot contain `;{}`. |
| `clearCssVars()` | Revert everything this plugin set |
| **`setBackgroundMedia({ url, kind?, size?, opacity?, loop?, muted?, autoplay? } \| null)`** | Global wallpaper — **image or video**. Preferred API. |
| `setBackgroundImage({ url, size?, opacity? } \| null)` | Legacy: images only. Still works; prefer `setBackgroundMedia`. |
| `h(tag, content?, props?)` | Build a node description |
| `refresh()` | Re-render this slot (async data arrived) |

### Wallpapers: images and videos

```js
// a video shipped inside your own plugin
api.setBackgroundMedia({ url: 'lcode-plugin://acme.wallpaper/assets/bg.mp4', opacity: 0.85 })

// an image
api.setBackgroundMedia({ url: 'lcode-plugin://acme.wallpaper/assets/bg.webp' })
```

**Two ways to change appearance — pick by intent:**

| Intent | Use | Who decides the details |
|---|---|---|
| Recolor the UI | `setCssVars` | Host defines tokens; you supply values |
| Simple wallpaper | `setBackgroundMedia` | Host owns the layer |
| Layering, positioning, decorative overlays, complex composition | `injectStyles` | **You** — write the CSS |

`injectStyles` is the escape hatch for anything the convenience APIs cannot express. It gives you
a scoped `<style>` element (created and owned by the host — you only supply text):

```js
api.injectStyles(`
  #lcode-plugin-background { z-index: -1; }
  .shell { background: rgba(20, 20, 28, 0.55); }
`)
```

Rules: styles are keyed per plugin (injecting again replaces your previous sheet), they are removed
when your plugin unloads, and `@import` is rejected — reference your own assets with
`lcode-plugin://<id>/<path>` instead.

This split mirrors DSH: its host only exposes a style-injection entry point
(`webserver/index-inject`); z-index and translucency rules live in the plugin's own CSS.

**Host baseline you can rely on:** `.shell` (menubar, sidebar, conversation) always establishes a
stacking context above full-window overlays, and `body` has no background of its own — the canvas
color comes from `--bg-canvas` on `.shell`. So a full-window background needs the canvas token to
be translucent; that part is your call, not a host rule.

**`lcode-plugin://<plugin-id>/<path-inside-package>` is the right way to reference your own
files.** The host serves only that plugin's directory and only media types (images, videos,
fonts) — it is not a general file-read channel. This is why you never need to base64-encode a
multi-megabyte video into a `data:` URL.

`kind` is inferred from the extension (`.mp4`/`.webm`/`.ogv`/`.mov` → video, everything else →
image); pass it explicitly if the URL has no useful extension. Videos default to `loop` + `muted`
+ `autoplay`, which is what a wallpaper needs.

Also accepted: `https://`, `data:image/*`, `data:video/*`, `blob:`, `file://`.

### When the platform's asset route is not enough: register your own

Static assets go through a fixed extension allowlist. If you need anything that allowlist does not
cover — signed URLs, generated bytes, streaming, per-request authorization — **register your own
route from the host half** and point the client at it:

```js
// src/index.js  (host half)  — declare "/wallpaper" in contributes.routes FIRST
export async function activate(ctx) {
  await ctx.registerRoute('/wallpaper', async (request) => {
    // return { status, body, headers } — body is a string
    return { status: 200, body: pickFor(request.query), headers: { 'content-type': 'text/plain' } }
  })
}
```

```json
{ "contributes": { "routes": ["/wallpaper"] } }
```

```js
// src/client.js  (client half)
api.setBackgroundMedia({ url: 'lcode-plugin://my.id/wallpaper/bg.mp4' })
```

URL shape: `lcode-plugin://<plugin-id>/<your-route><rest>`. Your handler receives
`{ method, url, headers }` and returns `{ status, body, headers? }`; `rest` is the tail after your
route prefix, so one route can serve a whole namespace.

Rules:

1. **Declare first.** A path in `contributes.routes` is required; registering an undeclared path
   throws. The rule is the same as tools and prompt sections.
2. **Longest prefix wins.** Registering both `/media` and `/media/thumb` routes the more specific
   one first.
3. **Scoped per plugin.** Your route only answers under your own id; another plugin cannot claim it.
4. **Body is a string.** For binary, either put the file in the package and let the asset route
   serve it, or base64 it — this channel is text-only.
5. **Routes disappear with your plugin.** They are registered as effects and removed on unload.

This is exactly how DSH video skins work: its platform asset route is image-only, so the plugin
serves its own `/background.mp4` route.

**Invalid URLs throw.** This is deliberate: the old implementation returned silently, so a typo
looked exactly like "the wallpaper did nothing". Catch it if you want to fall back:

```js
try { api.setBackgroundMedia({ url }) } catch { api.setCssVars({ '--bg-canvas': '#14141c' }) }
```

### Changing colors: override tokens, not properties

```js
// correct — one override recolors the whole app
api.setCssVars({ '--bg-canvas': '#1b1b26', '--text-primary': '#e8e8f0' })

// wrong — you would have to enumerate every element that uses them
document.body.style.background = '#1b1b26'
```

Every component reads `var(--token)`, so overriding the token changes everything at once. Setting
concrete properties only affects what you happen to list, and produces "half dark, half light".

Useful tokens: `--bg-canvas`, `--bg-elevated`, `--bg-inset`, `--text-primary`, `--text-secondary`,
`--text-muted`, `--border-subtle`, `--border-strong`, `--accent`, `--accent-weak`.

### Building UI

```js
export function render({ slot, api }) {
  return api.h('div', api.h('span', 'hello'), { class: 'my-panel' })
}
```

`api.h(tag, content, props)` — `content` is a string or another `h()` node. Use `class`, not
`className` (the host maps it). Blocked tags: `script`, `iframe`, `object`, `embed`, `link`, `meta`,
`style`, `form`.

**Don't expect to import React.** The plugin module gets no React instance; `api.h` is the only way
to create elements.

## Reading configuration

The plugin's `config.json` (in its install directory, next to `lcode.json`) is exposed at module
evaluation time:

```js
const cfg = globalThis.__lcodePluginConfig ?? {}

export function render({ api }) {
  api.setCssVars({ '--bg-canvas': cfg.canvas ?? '#14141c' })
  return null
}
```

Read it at **module scope** — it is only set before the module is evaluated, and is removed
immediately afterwards so plugins cannot read each other's config.

## Rules

1. **No imports of other files.** The module is loaded from a `data:`/`blob:` URL; relative imports
   fail. Ship one self-contained file.
2. **No Node APIs.** This runs in the renderer: no `fs`, no `child_process`, no `process`.
3. **Do not touch `document` directly** for anything persistent. Use the `api` so the host can
   revert your changes when the plugin is disabled. (Reading `document` is fine.)
4. **Do not throw from `render`.** A throwing plugin is disabled for the rest of the session — it
   will not be retried, and the user sees nothing.
5. **`https:` or `data:` only** for image URLs. `file:` would let a plugin probe the local disk.

## Verifying it actually applied

`render` returning successfully does not mean the styles took effect. Check:

- `document.documentElement.dataset.lcodePlugins` lists your plugin id,
- the host log shows `渲染层已加载 N 个 client 插件：<id>`,
- the visible change is there (a theme change is obvious; a panel is not).

If the id is absent, the module failed to load — look for `用 blob 加载失败` / `用 data 加载失败` in
the console.
