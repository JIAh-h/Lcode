# 28 · 记忆系统设计

> 状态：**已实现**（`@lcode/memory-local`）。
> 相关：[09 上下文工程](./09-上下文工程与压缩策略.md)（缓存纪律）、[30 统一插件加载器](./30-统一插件加载器设计.md)。

## 1. 定位：默认的两层记忆

Lcode 有一套**开箱即用**的记忆，参考同类产品的默认形态：

| 层 | 存放 | 归属 | 谁写 |
|---|---|---|---|
| **用户记忆** | `~/.lcode/memory/USER.md` | 跟着人走，换项目也在 | 用户（可编辑）/ 模型显式写入 |
| **项目记忆** | 工作区的 `AGENTS.md` / `CLAUDE.md` / `.lcode/instructions.md` | 跟着仓库走，团队共享 | 人或团队；模型可追加 |

**不是**在会话内的事件日志（那是工作记忆，见 [06](./06-会话事件日志与可重放设计.md)），也**不是**压缩摘要（见 [09 §4](./09-上下文工程与压缩策略.md)）。

更强的记忆能力（三层记忆、可检索归档、审核流）属于**插件扩展**，不在默认实现里。

## 2. 注入位置与缓存纪律

记忆是**稳定内容**——只在用户改动时才变。因此它进**系统提示词的稳定前缀**（`systemPrompt.context('memory', …, { order: 850 })`），不是历史尾部。

| 位置 | 后果 |
|---|---|
| 系统提示词前缀（现在） | 一次写入，长期命中缓存 |
| 历史尾部追加 | 每轮都占"新增消息"额度，且每次写入都让尾部失效 |

**代价**：写入记忆会让前缀失效一次。所以写入必须是**显式批量动作**（用户点保存 / 模型在会话中写一次），不能每轮自动写。

**为什么 order 取 850**：排在 `runtime-context`（900）与时间（999）之前，让"人写的规矩"比"自动采集的上下文"更靠近前缀开头；同时排在 base（0）之后，保持人设在最前。

## 3. 容量上限

| 限制 | 值 | 理由 |
|---|---|---|
| 行数 | 200 | 超过 200 行后模型遵守率明显下降（同类产品的经验值） |
| 字符数 | 25,000 | 只有行数限制时，超长单行也能塞进来；只有字符限制时，短行能堆出巨量 |

两个上限都要。超限时**截断并如实标注**（`… (memory truncated at N lines / M chars)`），而不是无声撑大每一步的固定成本。

## 4. 写入触发：显式，不自主

**只在两种情况下写**：

1. 用户明确说「记住」「帮我记下来」；
2. 用户纠正了模型的做法并说明原因（「别用 npm，这项目用 pnpm」）。

**明确不写**：能从代码/配置读出来的（框架、包管理器、目录结构）、一次性任务细节、模型自己推断的东西。

**为什么不自主**：写记忆 = 一次缓存失效 + 两次工具调用（read + edit）。自主判断会带来三个风险：

| 风险 | 表现 |
|---|---|
| 误记泛滥 | 「这个项目用 TypeScript」也被记进团队共享的 `AGENTS.md` |
| token 浪费 | 每轮都发现"新的稳定事实"，反复读写 |
| 缓存失效 | 每写一次都让前缀失效，抵消掉 [09](./09-上下文工程与压缩策略.md) 里 98% 命中率的优化 |

成本约束：**一个会话最多 2~3 条**。

## 5. 写入通路：用现成的文件工具，不造专用工具

模型通过 **`edit` / `write`** 直接改记忆文件，没有专属的 `memory` 工具。

**理由**：专用写入口会绕过审批链（[12](./12-安全权限与沙箱模型.md) 的"越界一律问"）。用文件工具意味着记忆写入和普通文件修改走**同一条**策略判定，不留旁路。

这也让"记忆访问"是一次**可见的工具副作用**——可记录、可审批、可拒绝、可审计。

## 6. 无工作区会话的写入

「最近任务」这类未选工作区的会话也必须能写**用户记忆**（它不依赖工作区）。

实现上有一处例外（`permission-presets/hook.ts`）：

```
全部路径都落在可信写目录（PC `~/.lcode/memory/`）内 → 放行
任何一条落在别处                                → 仍按最保守方式拒绝
**不申报任何路径的只读工具**（如 session_search） → 放行（没有边界可越）
```

可信写目录（`policy.trustedWriteRoots`）只放开**写**，且是精确前缀匹配（`memory-evil/` 不能绕过）。

**为什么放开写**：记忆目录是应用自己的数据目录；「记住偏好」每次都弹审批只会训练用户无脑点允许，那比不问更危险。

## 7. 已知限制

| 限制 | 现状 | 影响 |
|---|---|---|
| 并发写同一 `AGENTS.md` | 读-改-写，后写覆盖 | 多 worker 并行时可能丢一条 |
| 跨会话自动总结 | 无 | 会话多了会累积重复条目 |
| 模型自主记忆的私有区 | 无（都进工作区文件） | 模型写的东西会进团队仓库 |
| 记忆检索 | 无（靠 `session_search` 找会话，不是找记忆） | — |

## 8. 接口

```ts
interface MemoryStore {
  /** 读取当前生效的记忆（已按上限裁剪）；返回值就是**真正会注入的文本** */
  read(input: { home: string; workspaceRoot?: string }): MemorySnapshot
  /** 整文件覆盖写用户记忆 */
  writeUser(input: { home: string; text: string }): MemoryFileInfo
  /** 读原文（编辑页首次打开） */
  readUser(input: { home: string }): string
}
```

`read` 返回**注入后的文本而非磁盘原文**——否则界面显示的内容与实际注入不一致，用户会以为自己写的东西生效了，其实被截断。
