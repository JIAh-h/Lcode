## 2. 产品宪法（不可妥协的三条）

这三条是 Lcode 的"人格"。任何功能设计若与它们冲突，要么改设计，要么走 [17-架构决策记录ADR.md](./17-架构决策记录ADR.md) 正式推翻并说明代价。

### 第一条 · 可解释优先于聪明

> **用户能问出"它为什么这么做"，并且一定能得到答案。**

Lcode 不追求"最像人的 agent"，追求"最可被追问的 agent"。每一条模型看到的上下文、每一次工具调用、每一个权限决策，都必须能追溯到日志里的一条具体事件。

**落地要求（硬性）**：

- 任何进入模型请求的内容，必须能从会话日志重建（**模型可见即可重放**）。
- 提供"时间轴回放"能力：用户能回到任意一步，看到当时**确切**的输入与输出。
- 提供"为什么"面板：给定一次工具调用，能列出它经过了哪些策略、谁批准的、依据是什么。

**反例（明确不做）**：不为了"显得流畅"而隐藏中间步骤；不为了"减少打扰"而合并不可追溯的内部推理。

### 第二条 · 用户拥有自己的数据与算力

> **代码、会话、凭据、插件，默认全部留在用户机器上。**

- **默认本地优先**：会话日志、索引、缓存、凭据全部落盘在本机，不经过 Lcode 自有服务器。
- **无强制账号**：不登录也能完整使用全部核心能力。
- **可 BYOK（Bring Your Own Key）**：用户自带模型凭据；凭据以"引用"形式存在于配置中，值永不进入 UI、日志、遥测。
- **可导出**：任何时刻能导出全部会话为人类可读格式（JSONL / Markdown）。
- **遥测默认关闭**，开启后也必须可逐项审查；提供 `lcode doctor --telemetry` 展示"到底会发什么"。

### 第三条 · 内核只提供机制，策略全部外挂

> **Lcode 的核心循环里不做业务判断。**

- 核心循环（`agent-loop`）只做三件事：**调模型、跑工具、重复**。
- 压缩、审批、沙箱、计划模式、子代理、技能、hook —— 全部是监听事件的插件。
- **可插拔不是营销词，是架构约束**：插件卸载时，世界必须精确回滚到加载前的状态。

**可检验的判据**：核心循环包（`@lcode/agent-loop`）的源码中，`if` 语句所判断的内容**不得涉及任何具体能力**（不得出现 `if (needsApproval)`、`if (tokens > limit)` 之类的分支）。CI 会有一条静态检查尝试守住这条线。

## 3. 用户定义

### 3.1 主用户：个人开发者（默认，MVP 目标）

| 维度 | 描述 |
|---|---|
| 画像 | 全职或半职业的软件工程师，1–5 年经验以上，日常在本地做真实项目 |
| 环境 | macOS / Windows / Linux 桌面；多模型账号（可能同时用 2–3 家） |
| 痛点 | ① 现有 agent 改了文件却说不清为什么；② 长任务跑到一半崩了要重来；③ 想定制但没有扩展点；④ 上下文一长就"变傻"或烧钱 |
| 诉求 | 可控、可查、可恢复、可定制 |
| 付费意愿 | 愿意为"省心 + 可审计 + 不丢工作"付费；对按 token 订阅敏感 |

### 3.2 次用户：小团队（v1.0 起）

| 维度 | 描述 |
|---|---|
| 画像 | 3–20 人研发团队，有共同代码规范与工具链 |
| 诉求 | 共享 agent 配置（preset）、共享技能、会话可分享、"新人上手即对齐" |
| 边界 | **不需要**企业级 SSO / 合规审计 / 配额管控（那是企业版的事，明确排除在 v1.0 之外） |

### 3.3 明确不是我们的用户（v1.0）

- 需要**完全托管云 IDE** 的用户（我们把代码留在本地）。
- 需要**企业级合规审计**的用户（我们提供证据，但不提供合规认证）。
- 非开发者（Lcode 默认用户看得懂 git diff 与终端输出）。

## 4. 技术宪法（关键决策与理由）

> 完整的决策上下文与代价分析见 [17-架构决策记录ADR.md](./17-架构决策记录ADR.md)。本节只给出结论，供所有文档引用。

| # | 决策 | 结论 | 一句话理由 |
|---|---|---|---|
| D1 | 语言与运行时 | **TypeScript + Node.js 22+**，ESM only | 与参考架构同源；一端代码覆盖主进程与插件；生态最全 |
| D2 | 桌面外壳 | **Electron**（主进程承载 agent runtime） | 需要 Node 原生能力（子进程、PTY、fs）+ 一套 Web UI 技术栈；Tauri 的 Rust 侧无法直接运行 Node 插件生态 |
| D3 | UI 技术栈 | **React + TypeScript + Vite**；样式用 CSS 变量主题，不引入重型组件库 | 会话流是虚拟列表场景，React 生态成熟；主题需支持浅/深色切换 |
| D4 | 状态模型 | **append-only 事件日志（SessionEvent）**，消息历史是**派生投影** | 可重放、可分叉、可恢复的唯一地基 |
| D5 | 压缩原语 | **surface replace**（追加一条声明替换区间的 surface 事件），**不做删除** | 原始事实保留 ⇒ 重放确定；扇出与审计仍可还原 |
| D6 | 扩展模型 | **服务（Service）+ 事件（Event）+ 可逆副作用（Effect）**；三类事件域 | 内核最小、能力最大可替换；卸载即回滚 |
| D7 | 事件派发模式 | **emit / waterfall / parallel / serial** 四种，模式属于事件的公开契约 | 让"观察 / 拦截 / 广播 / 顺序"的语义写在类型上 |
| D8 | 工具模型 | 工具返回**结构化规范值** + 纯投影渲染；UI 卡片是独立投影 | 同一份值同时服务模型、Code Mode、UI，三者不可能分叉 |
| D9 | 工具参数 | **不可被中间件改写** | 历史 / 审计 / UI / 执行必须一致 |
| D10 | 策略优先级 | 可重排策略用 `waterfall`；**不可撤销的终局拒绝用单调 guard（类型上无 allow）** | 从类型上杜绝"顺序相关的翻盘" |
| D11 | 权限缺省 | **fail-closed**：无审批应答者 = 拒绝；并行分类器非精确 `true` = 独占 | 不确定时选更安全的一侧 |
| D12 | 会话持久化 | **SQLite（索引 / 查询 / 会话元数据）+ JSONL（会话日志的权威归档）** | SQLite 管"找到它"，JSONL 管"完整保存它"；两者职责不重叠 |
| D13 | 沙箱 | **OS 原生机制**：macOS 沙箱配置文件 / Linux Landlock + seccomp / Windows AppContainer + Job Object | 不引入 VM，保持启动速度与本地体验 |
| D14 | 插件隔离 | 插件运行在**独立 utility process**，通过类型化 RPC 与内核通信 | Node 同进程无法做安全边界，进程隔离是唯一诚实的方案 |
| D15 | 内部协议 | **类型化 RPC**：从 TypeScript 类型图生成描述符，客户端消费生成产物 | 前后端类型安全的单一真相来源 |
| D16 | 外部协议 | **JSON-RPC 2.0 over stdio**（ndjson）；stdout 即协议，日志走 stderr | 最容易接入，也最容易用 shell 调试 |
| D17 | 会话标识 | 会话 id 全局唯一；**agent 与会话共享同一个 id** | 避免"两个身份"带来的路由歧义 |
| D18 | 时间处理 | 持久事件用 **epoch ms（number）**；展示层才做本地化 | 时区不属于事实 |
| D19 | **模型配置分层** | **六层，高覆盖低**：单次覆盖 > 会话选择 > 工作区预设 > 用户设置 > 适配器基座 > schema 默认；**逐字段合并，不整块替换** | 让"部署方预置 / 团队共享 / 个人覆盖 / 单次临时改"同时成立 |
| D20 | **默认模型选择的归属** | `@lcode/agent-default-model`（`ctx.agentDefaultModel`）是"当前用哪个模型"的**唯一权威**；供应商实现归各自适配器（注册进 `ctx.llm`） | 一份状态只有一个主人；否则 UI、CLI、协议三条入口会各自为政 |
| D21 | **模型选择不做自动化** | **不做**按任务自动路由、自动测速、自动降级省钱；自动能力若将来要做，必须是**显式、可审计、默认关闭**的插件 | 自动路由会让"同样输入产生不同行为"，直接破坏可重放与可预期性 |
| D22 | **凭据解析优先级** | 进程环境变量 > `Lcode Home/.env` > 项目 `.env` > OS keychain 记录；**每次操作重新解析**；UI 必须显示"当前生效来源" | 轮换的 key 对下一个请求立即生效；同时避免用户"改了没生效"无法自查 |

### 5.1 硬性约定

| 约定 | 说明 |
|---|---|
| **依赖方向** | 扩展插件只依赖**接口包**，绝不依赖具体实现包。`tool-fs` 依赖 `fs`，不依赖 `fs-local`。 |
| **ctx key 命名** | 单数 = 一个引擎 / 策略 / 控制器 / 存储；复数 = 注册表或拥有多个具名成员的服务。 |
| **每个包必须有 README** | 含：职责、API、事件、扩展点、`Known Limitations`。 |
| **ESM only** | `"type": "module"`；包间引用用包名，包内相对引用带 `.ts` 后缀。 |
| **零循环依赖** | `scope` 位于 `session` 与 `system-prompt` 的共同下游，专门为避免环。 |

## 6. 术语表

> **本表是强制的。** 所有文档必须使用这里定义的字面量，不得使用同义词。

| 术语 | 英文 | 定义 |
|---|---|---|
| **会话** | session | 一段完整的交互历史，由 append-only 事件日志承载；有全局唯一 id |
| **轮** | turn | 一个封闭区间：从"认领第一个输入"到"没有欠账"；含零或多个步 |
| **步** | step | 一次模型请求 + 它请求的工具执行 |
| **表面** | surface | 事件日志中会产生模型可见消息的有序投影，只含 `user/message` / `assistant/message` / `tool/result` 三类事件 |
| **表面操作** | surfaceOp | `append` 或 `{ op: 'replace', start, end }`；**压缩的唯一原语** |
| **派生** | derive | 从事件日志计算出投影（如消息历史、待办列表）的纯函数过程 |
| **种子** | seed | 恢复 / 分叉 / 重放时，作为起点注入的既有事件序列 |
| **接缝** | seam | 可替换能力的三角：接口（Definition）/ 实现（Provider）/ 消费者（Consumer） |
| **服务** | service | 通过 `ctx.<key>` 被查找的能力提供者 |
| **事件** | event | 命名的可订阅通知；有四种派发模式 |
| **副作用** | effect | 可逆的注册操作；注册即返回撤销器 |
| **撤销器** | disposer | 撤销一次注册的函数；卸载插件时被调用 |
| **瀑布** | waterfall | 洋葱中间件式事件：`(args, next) => Result`；调用 `next()` 委托，直接返回则短路 |
| **守卫** | guard | 单调终局策略：只能拒绝或弃权，**类型上没有 allow** |
| **作用域** | scope | 不透明的注册作用域标识；Lcode 用活体 `Agent` 对象充当 |
| **规范值** | canonical value | 工具返回的结构化、无损 JSON 值；模型可见文本由它纯投影而来 |
| **卡片** | card | 工具调用/结果的 UI 渲染意图（`generic` / `terminal` / `diff` / `search` / `read` / `web`） |
| **预设** | preset | 单个 agent 会话级别的插件组合（`agent.cordis.yml`） |
| **集束** | bundle | 进程级别的插件补丁层（`cordis.patch.yml`） |
| **配置档** | profile | 命名的插件装配（列出它叠加的集束） |
| **时间轴** | timeline | Lcode 的核心 UI：会话内任意位置的可见化索引，支持回放与分叉 |
| **检查点** | checkpoint | 时间轴上一个可回放的稳定点（通常是 turn 边界） |
| **代码模式** | code mode | 让模型写代码调用工具（工具自动变成 `await tools.<name>(args)`） |
| **模型可见即可重放** | model-visible means logged | 核心不变量：任何进入模型请求的内容必须能从日志重建 |
| **模型选择** | ModelSelection | 一次请求用哪家哪个模型及其参数（provider / model / maxTokens / reasoningEffort / temperature） |
| **适配器** | adapter | 一个模型供应商的实现（`LlmAdapter`），注册进 `ctx.llm`；消费方按 provider 名查找，绝不 import 具体包 |
| **凭据引用** | credentialRef | 指向"一个可解析的来源"的名字（如 `ANTHROPIC_API_KEY`）；**值本身永不出现**在 settings、日志、UI、导出中 |

## 8. 常见误用与澄清

下面这些是写作与评审中最容易跑偏的地方，提前钉死。

### 8.1 "可重放"不等于"能撤销"

- **可重放**：能重建出"当时模型看到了什么、做了什么"。这是**观察**能力。
- **撤销**：能把文件系统退回某个状态。这是**变更**能力，需要额外的快照机制。
- MVP **只承诺可重放**；文件级撤销（checkpoint / revert）属于 v0.3，见 [14-产品路线图与里程碑.md](./14-产品路线图与里程碑.md)。

### 8.2 "插件"不等于"用户脚本"

Lcode 的插件是**完整的 Cordis 插件**（可注册服务、工具、事件监听、提示词段落），运行在独立 utility process 中，通过类型化 RPC 与内核通信。它不是"配置片段"，也不是"提示词模板"。

用户要的"简单定制"由三层递进满足：

```
① 配置档 / 预设（yml，改装配与参数）      ← 零代码
② 技能（SKILL.md + 可选脚本）             ← 写文档
③ 插件（TypeScript 包）                   ← 写代码
```

### 8.3 "本地优先"不等于"不能联网"

本地优先指的是 **Lcode 自身不托管你的数据**。调用模型当然要联网（除非用本地模型）；联网获取文档当然要联网。判断标准是：**数据流向谁**，而不是**是否使用网络**。

### 8.4 "团队协作"不等于"云端 SaaS"

v1.0 的团队能力是**同构本地能力的共享**：共享 preset 文件、共享技能包、导出/导入会话、基于文件系统的同步（用户自选 git / 网盘 / NAS）。我们**不做**自建协作服务器。

### 8.5 数字口径约定

| 指标 | 口径 |
|---|---|
| **冷启动**（cold start） | 进程不存在 → 主窗口可交互（macOS M1 / 16GB 基准机） |
| **热启动**（warm start） | 进程已在运行（窗口关闭或最小化）→ 窗口重新可交互 |
| **渲染进程重载**（reload） | 渲染进程重建（崩溃恢复 / 开发态 HMR）→ 重新可交互 |
| 首 token 延迟 | 从"用户回车"到"UI 出现第一个字符"（不含模型排队） |
| 工具调用延迟 | 从 `tool/call` 落盘到 `tool/result` 落盘（不含工具自身执行） |
| 日志膨胀率 | 会话日志字节数 ÷ 模型可见内容的字节数 |
| 重放准确率 | 重放重建的历史与实时历史逐字节一致的会话占比 |
| 内存 | 稳态 RSS（含一个 1 万事件会话），不含临时峰值与构建期 |

> **三种启动口径必须分开报数。** 只报一个"启动 ≤2.5s"会掩盖两件事：① 关窗再打开是否要重走全过程；② 渲染进程崩溃恢复是否把状态一起弄丢。这两件事的用户感受与冷启动完全不同（口径与预算见 [10 §7](./10-桌面客户端设计.md#7-性能预算)，需求见 [03 §4.1](./03-PRD-需求规格说明.md#41-性能nfr-perf)）。

### 8.6 "我们是一个 harness" 不是定位

这是最容易被误读的一条，必须在所有对外与对内材料里保持一致。

| 说法 | 是否成立 |
|---|---|
| "Lcode 是一个 agent harness" | ✅ 成立，但这是**形态描述**，不是定位 |
| "Lcode 是通用 agent 平台" | ❌ **不成立**，与 §3 用户定义和 §2 第三条冲突 |
| "Lcode 是可插拔的通用底座" | ❌ **不成立**，那是 DSH 的定位，不是我们的 |

**准确表述**：

> Lcode 是**面向开发者、以代码为主战场**的 agent 产品。它的内核是通用的（因为"只提供机制"是第三条原则的必然结果），但**产品身份是垂直的**。

**为什么内核通用不等于定位通用**：可重放的价值 ≈ **副作用的不可逆性 × 决策的不透明性**。改生产代码、执行不可逆命令、装依赖这三类场景里它是刚需；写报告、做表格里它是玩具。详见 [01 §6.4 定位辨析](./01-产品愿景与定位.md#64-定位辨析我们是-harness-但不是一个通用-harness)。

**三条纪律**（违反即为定位漂移）：

1. 对外话术一号卖点只说 **能查 / 能倒带 / 能恢复**，不提"可插拔"。
2. 内核保持小；任何"为了让内核更通用"的抽象，必须先回答"它服务哪条垂直用户旅程"。
3. 护城河压在**生态**（插件 / 技能 / 预设 / 社区约定），不压在架构。

**与 DSH 的关系**：DSH 是**潜在的底座供应商**，不是竞品。在同一格和开源平台比拼插件灵活性，必输。

### 8.7 术语速查：不要混用的三组词

| 容易混用 | 正确区分 |
|---|---|
| **形态 / 定位** | 形态 = 架构长什么样（harness）；定位 = 为谁解决什么问题。**形态相同不代表定位相同。** |
| **可重放 / 可撤销** | 可重放 = 能重建"当时发生了什么"（观察）；可撤销 = 能把状态退回去（变更）。见 §8.1。 |
| **内核通用 / 产品通用** | 内核通用是**实现手段**；产品通用是**市场定位**。前者是后者的必要条件，不是充分条件。 |
