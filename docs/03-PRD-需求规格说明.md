## 2. 用户旅程

以下四条旅程贯穿全部需求。每条需求都应能回答"它服务哪条旅程的哪一步"。

### 2.1 旅程 J1 · 老陈重构一个模块（主线旅程）

```
起点：老陈想把手写的 JSON 解析逻辑换成结构化解析，涉及 7 个文件。

①  打开工作区           → 首次信任确认（SEC-TRUST-001）
②  描述任务             → 会话创建（FR-SESSION-001）
③  agent 先探索         → 计划模式开启，只读工具可用（FR-PLAN-001）
④  产出计划，老陈审阅   → 计划审阅交互（UX-PLAN-002）
⑤  执行，逐个文件改     → diff 卡片 + 审批（FR-TOOL-004 / FR-PERM-003）
⑥  中途老陈想插话       → 转向（FR-AGENT-002）
⑦  第一次请求上下文爆了 → 压缩 + 可回放（FR-COMPACT-001 / FR-REPLAY-002）
⑧  老陈不放心，倒带     → 时间轴回放，看第 12 步的完整请求（FR-REPLAY-001）
⑨  想试试另一条路       → 从第 8 步分叉（FR-REPLAY-004）
⑩  完工，导出给同事看   → 会话导出（FR-DATA-002）
```

### 2.2 旅程 J2 · 老陈排查生产 bug

```
①  贴报错 + 相关文件      → 附件与会话引用（FR-SESSION-004）
②  agent 检索代码、读日志 → 检索与读取工具（FR-TOOL-002）
③  agent 要求跑一个命令   → 终端卡片 + 审批（FR-PERM-003）
④  跑出结果，定位到问题   → 工具结果 spill 处理（FR-COMPACT-003）
⑤  老陈想知道为什么这么判 → "为什么"面板（FR-REPLAY-003）
```

### 2.3 旅程 J3 · 老陈给 Lcode 加一个内部服务

```
①  写一个插件接内部代码检查 → 插件 SDK（EXT-PLUGIN-001）
②  本地加载并调试           → 开发态插件加载（EXT-PLUGIN-004）
③  在预设里启用它           → 预设编辑（FR-PRESET-001）
④  分享给团队               → 预设导出（FR-TEAM-001）
```

### 2.4 旅程 J4 · 小林把团队用法固化下来

```
①  配置团队规范（提示词 + 工具集） → 预设（FR-PRESET-001）
②  保存为共享预设                  → 团队预设（FR-TEAM-001）
③  新人拉取后用同一套              → 预设导入（FR-TEAM-002）
④  关键操作可审计                  → 审计视图 + 导出（FR-REPLAY-003 / FR-DATA-002）
```

## 3. 功能需求

### 3.1 会话（`FR-SESSION`）

| 编号 | 需求 | 优先级 | 版本 | 验收要点 |
|---|---|---|---|---|
| `FR-SESSION-001` | 用户可创建新会话，会话有全局唯一 id，agent 与会话共享同一个 id | Must | v0.1 | 创建后日志首条事件为轮开始；id 在 UI 与导出中一致 |
| `FR-SESSION-002` | 会话列表可展示、搜索、重命名、删除；支持按工作区分组 | Must | v0.1 | 万级会话下列表响应 ≤ 200ms |
| `FR-SESSION-003` | 会话可恢复（resume）：重启应用后能继续上次会话，派生历史与编号连续 | Must | v0.1 | 恢复后直接发消息成功；无孤立工具调用 |
| `FR-SESSION-004` | 用户可附加文件、图片、代码片段作为输入，附件被持久化引用而非内联 | Should | v0.1 | 附件在日志中表现为引用；导出时可选择是否内联 |
| `FR-SESSION-005` | 会话可引用另一个会话（跨会话快照）作为上下文 | Could | v0.5 | 被引用会话的内容以"不可信消息"入上下文 |
| `FR-SESSION-006` | 会话支持"清空上下文但保留日志"（相当于开新一代，历史仍在） | Should | v0.3 | 清空后日志可见分界线事件 |
| `FR-SESSION-007` | 每个会话可独立选择模型与参数，切换时记录请求头变化 | Must | v0.1 | 切换模型后下一步请求头可见新配置 |
| `FR-SESSION-008` | 同一会话可中途切换模型而不丢失历史 | Should | v0.2 | 切换后历史照常派生；无格式错误 |

### 3.2 回放与时间轴（`FR-REPLAY`）—— **核心差异化**

| 编号 | 需求 | 优先级 | 版本 | 验收要点 |
|---|---|---|---|---|
| `FR-REPLAY-001` | **时间轴回放**：用户可定位到会话内任意一步，查看当时**确切**的模型输入（system prompt、工具列表、消息历史） | Must | v0.1 | 展示内容与当时请求逐字节一致（由不变量测试保障） |
| `FR-REPLAY-002` | 回放支持"被压缩掉的内容"查看：压缩前后的内容都可展开 | Must | v0.3 | 压缩区间内原始事件可查看 |
| `FR-REPLAY-003` | **"为什么"面板**：给定一次工具调用，展示它经过的策略链、审批结果、决策依据 | Must | v0.2 | 每一次调用都能列出完整链路，无空白 |
| `FR-REPLAY-004` | **从任意点分叉**：可从某个检查点分叉出新会话，两边独立演进 | Must | v0.3 | 分叉点后的历史不污染原会话；分叉点不在未闭合轮内 |
| `FR-REPLAY-005` | 检查点标记：轮边界自动成为检查点，用户可手动命名关键检查点 | Should | v0.3 | 检查点可从 UI 直接跳转 |
| `FR-REPLAY-006` | 回放态只读：回放中不允许发消息，需显式"回到当前"或"从此分叉" | Must | v0.3 | 回放态输入框禁用并给出解释 |
| `FR-REPLAY-007` | 会话内的 diff 变更视图：按文件聚合所有变更，可跳到对应步骤 | Should | v0.2 | 变更列表与日志中的文件操作一致 |
| `FR-REPLAY-008` | 导出可读回放：导出为单文件 HTML，包含完整时间轴与请求快照 | Could | v0.5 | 导出文件离线可打开，无需 Lcode |

### 3.3 工具系统（`FR-TOOL`）

| 编号 | 需求 | 优先级 | 版本 | 验收要点 |
|---|---|---|---|---|
| `FR-TOOL-001` | 内置文件工具：读取（支持行窗口）、写入、编辑（唯一匹配替换） | Must | v0.1 | 编辑默认要求唯一匹配；不唯一时报错而非猜测 |
| `FR-TOOL-002` | 内置检索工具：按内容检索（grep）与按路径匹配（glob） | Must | v0.1 | 结果分组展示；截断时明确标注"不完整" |
| `FR-TOOL-003` | 内置 shell 工具：执行命令，支持前台与后台 | Must | v0.1 | 结构化返回退出码/信号/超时/输出；后台返回作业 id |
| `FR-TOOL-004` | 内置终端工具：持久 PTY 会话，支持打开/发送/读取/中断/关闭/列表 | Should | v0.3 | 会话按所属 agent 隔离，不可越权操作 |
| `FR-TOOL-005` | 网页工具：搜索与抓取 | Should | v0.2 | 抓取结果截断时有明确标注；来源可追溯 |
| `FR-TOOL-006` | 工具返回**结构化规范值**，模型可见文本由纯投影产生 | Must | v0.1 | 同一份值可同时驱动模型文本、Code Mode、UI 卡片 |
| `FR-TOOL-007` | 工具卡片六种形态：`generic` / `terminal` / `diff` / `search` / `read` / `web` | Must | v0.1（前四种） | 卡片可由日志纯重放重建 |
| `FR-TOOL-008` | 工具参数可被声明式 schema 校验，非法参数成为结构化错误而非抛异常 | Must | v0.1 | 非法参数不中断会话，模型可自我纠正 |
| `FR-TOOL-009` | 工具支持并行调度：并发安全的工具可重叠执行，其余构成顺序屏障 | Should | v0.2 | 并发上限可配置；结果按模型顺序落盘 |
| `FR-TOOL-010` | 工具声明超时；超时映射为结构化错误码 | Should | v0.2 | 超时不影响后续步骤 |
| `FR-TOOL-011` | 单个工具的可见性可被限制（白名单/黑名单），且限制只影响继承来的工具 | Must | v0.3 | 子代理保留自己注册的回话工具 |
| `FR-TOOL-012` | 工具集可按预设裁剪，且裁剪在呈现、查找、执行三处保持一致 | Must | v0.3 | 不存在"能列出但执行被拒"的不一致 |
| `FR-TOOL-013` | 支持"代码模式"：模型写代码调用工具，工具自动变为可等待的函数 | Could | v0.5 | 子调用仍走完整权限流水线 |

### 3.4 权限与审批（`FR-PERM`）

| 编号 | 需求 | 优先级 | 版本 | 验收要点 |
|---|---|---|---|---|
| `FR-PERM-001` | 三条正交权限轴：沙箱模式、审批策略、权限预设 | Must | v0.2 | 预设切换同时写两条轴，可审计 |
| `FR-PERM-002` | 沙箱模式至少三种：只读、工作区可写、完全访问 | Must | v0.2 | 越界写入被实际拦截（三平台各有验收） |
| `FR-PERM-003` | 审批弹窗展示**操作、依据、影响面**，结果四选一：一次性允许/拒绝/取消/不可用 | Must | v0.2 | 缺失应答者时默认拒绝 |
| `FR-PERM-004` | 审批是**一次性**的，不提供"永久允许"；要永久须显式切换预设 | Must | v0.2 | UI 不出现"记住选择" |
| `FR-PERM-005` | 单调守卫：部署方可设置不可撤销的红线拒绝 | Must | v0.2 | 守卫无法把已有拒绝翻回允许 |
| `FR-PERM-006` | 审批与策略决策都落盘为可审计事件 | Must | v0.2 | 可从日志重建"谁在何时基于什么批准了什么" |
| `FR-PERM-007` | 工作区信任：首次打开新工作区需显式确认信任状态 | Must | v0.1 | 未信任工作区默认更保守 |
| `FR-PERM-008` | 高风险动作强制审批：写工作区外、网络出站、首次出现的高危命令 | Must | v0.2 | 无法被配置关闭（属于红线） |

### 3.5 计划模式（`FR-PLAN`）

| 编号 | 需求 | 优先级 | 版本 | 验收要点 |
|---|---|---|---|---|
| `FR-PLAN-001` | 计划模式：只读探索 → 产出计划 → 用户批准 → 执行 | Must | v0.2 | 计划模式下写工具不可用 |

### 3.6 上下文工程（`FR-CTX`）

| 编号 | 需求 | 优先级 | 版本 | 验收要点 |
|---|---|---|---|---|
| `FR-CTX-001` | 系统提示词由多个来源分段装配，支持排序与作用域覆盖 | Must | v0.1 | 同名时作用域内覆盖全局 |
| `FR-CTX-002` | 工作区指令文件（如 `AGENTS.md`）自动注入；内容变化时**仅变化后**重新注入 | Must | v0.1 | 内容不变时不重复注入（可验证） |
| `FR-CTX-003` | 按需注入子目录指令：工具触达新目录时发现并注入 | Should | v0.3 | 有去重机制，不重复注入同一版本 |
| `FR-CTX-004` | 动态上下文只在变化时物化，避免每步重发 | Must | v0.1 | 用 KV 缓存影响的度量验证 |
| `FR-CTX-005` | 所有来自仓库/网页的内容必须被包裹并转义，防止逃逸 | Must | v0.1 | 内容中出现的包裹结束标记被转义 |
| `FR-CTX-006` | 提供仓库结构摘要（文件树 + 关键文件识别）作为可开关的上下文 | Should | v0.3 | 大仓库下不拖慢首 token |
| `FR-CTX-007` | 支持 `@` 引用文件、会话 | UX 见 `UX-INPUT-003` | v0.3 | 引用解析为路径 id，不内联内容 |
| `FR-CTX-008` | 用户可查看当前会话实际生效的全部上下文来源与字节数 | Should | v0.2 | 与请求快照一致 |

### 3.7 压缩（`FR-COMPACT`）

| 编号 | 需求 | 优先级 | 版本 | 验收要点 |
|---|---|---|---|---|
| `FR-COMPACT-001` | 压缩采用 **surface replace**：追加声明替换区间的记录，**不做删除** | Must | v0.3 | 被遮蔽的原始事件仍可在日志中查看 |
| `FR-COMPACT-002` | 轻量压缩优先：先用零模型成本的手段（结果剪枝） | Must | v0.3 | 剪枝先于摘要执行，可观测顺序 |
| `FR-COMPACT-003` | 超大工具结果落盘（spill）：内联替换为预览 + 定位符，模型可按需取回 | Must | v0.3 | 落盘失败不影响原结果的成功语义 |
| `FR-COMPACT-004` | 摘要压缩：选择区间生成摘要替换；断言摘要严格小于原文 | Should | v0.5 | 不满足断言则拒绝压缩 |
| `FR-COMPACT-005` | 压缩边界不得切断工具调用与结果的配对 | Must | v0.3 | 压缩后请求仍然合法 |
| `FR-COMPACT-006` | 压缩触发时机仅限两个明确边界：步前压力检测、请求错误恢复 | Must | v0.3 | 不在流式中途压缩 |
| `FR-COMPACT-007` | 提供 token 用量与压力测量，可观测 | Should | v0.2 | 用量与实际请求一致 |
| `FR-COMPACT-008` | 上下文溢出恢复：捕获规范溢出错误后压缩并重试 | Should | v0.5 | 按错误码路由，不按错误文本 |

|---|---|---|---|---|

| `FR-MODEL-008` | 配置分层：单次覆盖 > 会话选择 > 工作区预设 > 用户设置 > 适配器基座 > schema 默认，**逐字段合并** | Must | v0.1 | 只改 `baseUrl` 时不影响模型清单 |

| `FR-MODEL-010` | 保存配置后自动做**连通性自检**，给出可读的失败归因（密钥无效 / 地址不通 / 模型不存在 / 超时 / 本地未运行 / 未配置） | Must | v0.1 | 六类错误各有独立文案 |

| `FR-MODEL-001` | 模型适配器可插拔；至少支持 2 家云端 + 1 个本地运行时 | Must | v0.1 | 换适配器不需改调用方 |
| `FR-MODEL-002` | 流式协议统一：文本、推理、工具调用片段、用量、结束原因 | Must | v0.1 | 结束原因统一为有限枚举 |

| `SEC-CRED-003` | 凭据值优先存 OS 钥匙串，回退到 0600 权限文件 | Must | 回退路径有警告 |
| `SEC-PLUGIN-001` | 插件清单必须声明权限：文件范围、网络域名、spawn、环境变量 | Must | 未声明即拒绝 |
| `SEC-PLUGIN-002` | 插件安装在独立进程运行，可被整体终止 | Must | 杀掉进程后内核状态完好 |
| `SEC-PLUGIN-003` | 插件安装时展示权限并需用户确认 | Must | 权限变更时重新确认 |
| `SEC-INJECT-001` | 来自仓库/网页的内容必须被包裹并转义，不可作为指令 | Must | 逃逸字符被正确转义 |
| `SEC-INJECT-002` | 高风险动作强制审批，且不可被配置关闭 | Must | 无配置项可绕过 |
| `SEC-TRUST-001` | 工作区信任：首次打开需显式确认；未信任时默认更保守 | Must | 未信任下写操作被拦截 |
| `SEC-AUDIT-001` | 所有权限相关决策落盘为可审计事件 | Must | 可重建完整决策链 |
