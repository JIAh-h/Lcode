# @lcode/session

> 骨架层核心（文档 20 §5.1，`ctx.sessions`）：**append-only 事件日志的唯一 owner**。
> 追加、读取、派生投影、分叉。冻结模块（改接口走 ADR）。

## 职责

- 追加事件（`seq` 由本模块分配，调用方不得传入；恒等于追加前的日志长度，不变量 I2）
- 批量追加（原子性：要么全部可见，要么全部不可见）
- 读取（按区间，逐条事件）
- 派生投影 `deriveMessages()`（纯函数语义：同样的日志必然得到同样的结果）
- 分叉 `fork(cutAtSeq)`（按"安全切点"复制出新会话）
- 生命周期分界线 `markEndSeed()`

## 不做什么

- 不渲染、不压缩（压缩只是"追加一条 surface 事件"）、不判断业务策略。

## 不变量

| # | 不变量 | 违反后果 |
|---|---|---|
| S1 | `seq` 单调、无空洞：第 n 条事件的 `seq === n - 1` | 回放定位失效 |
| S2 | 日志是**唯一真相**：任何进入模型请求的内容都能从日志重建（I1） | "可重放"承诺破产 |
| S3 | `surfaceOp: replace` 的区间必须落在当前 surface 范围内（I4） | 投影越界崩溃 |
| S4 | 事件 `data` 必须无损 JSON 序列化（I5） | 落盘失败或静默丢字段 |
| S5 | 追加是**同步提交**到内存 + 有界批写磁盘；`flush()` 是静默屏障 | 崩溃后丢更多 |

## 事件词汇表（SessionEventMap）

开放接口（声明合并）：插件可以 `declare module '@lcode/session'` 扩展事件类型（文档 06 §2.2）。

## Known Limitations

- 单会话日志不自动分片（见 22 §9 容量与保留）。
- `fork()` 不支持落在未关闭的轮内（ES-FORK_BOUNDARY_INVALID）。
- 当前实现为**内存版**；持久化（JSONL / SQLite）由 `session-persistence` 能力层接入（批次 ②）。
